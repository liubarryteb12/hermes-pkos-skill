# 规则卡：X/Twitter 帖子（card-x）

## 适用
`x.com/<user>/status/<id>` 或 `twitter.com/...`（归一化已统一为 x.com，见契约 §四）。

## 认证边界（hard rules）
- 不自动登录、不读取浏览器 Cookie、凭据不落日志与命令回显。
- 只走公开可及路径；拿不到就是拿不到，进入降级链末端「问用户」。

## 通道阶梯（按序尝试，失败记录原始错误再换下一条）
1. **L1 Reader**：r.jina.ai 对多数公开帖可直接返回正文+评论结构。
2. **L2 浏览器渲染**：会话内浏览器工具打开帖子页抽取正文。
3. **放弃**：标 error 问用户（提供截图/粘贴文本等替代输入方式）。

## 平台硬约束（实战沉淀）
- 高频请求触发风控：每次操作间隔 2–3 秒；批量收 X 帖时强制遵守。
- 数据中心 IP 上频繁调用有封号风险：批量任务前提醒用户。
- 评论区分隔线、引用嵌套是正常结构，不是登录墙残留——验收 gate 判「阻断语」要看正文主体而非引用块。

## front matter 惯例
- `author` 写 `[[@handle]]` 并检查 `_作者/` 是否已有聚合页（没有则在 INDEX 挂载时提示补占位，不代建）。
- `published` 取帖子时间戳；取不到就缺省并 INFO 说明。
