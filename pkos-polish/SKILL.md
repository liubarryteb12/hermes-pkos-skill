# Analysis→Polish 接口协议（锁死）

**上游（pkos-analysis）每条发现必须携带三元组**：

```
证据（原文精确定位引用）
背后意图（这个写法在伪装什么/回避什么）
建议动作（可执行的最小修改）
```

**铁律：说不清解决哪条发现的改动，一律不做。** 没有"顺手美化"。改动的唯一合法来源是发现条目。

# 双向失败模型（两侧都要检查并给结论）

| 失败方向 | 症状 | 检查问题 |
|---|---|---|
| **AI 痕迹残留** | 破折号滥用、三段式凑数、意义拔高、空洞总结 | 改完后还有触发词命中吗？ |
| **磨成中性腔** | 为去味而删掉锋利观点、具体数字、个人风格，文字变白开水 | 事实数量与观点锐度对比改前有损失吗？ |

交付结论必须同时回答两问，缺一即不合格。

# 五维评分卡（各 0–10，≥35 才许交付）

| 维度 | 10 分锚点 |
|---|---|
| 直接性 | 开头即事，无铺垫套话 |
| 节奏 | 长短句自然交错，读起来像人喘气 |
| 信任度 | 具体数字/来源在场，无模糊归因 |
| 真实性 | 有立场有取舍，不像模板生成 |
| 精炼度 | 删无可删，每个词都在干活 |

**<35 = 回炉**：重新对照发现表逐条检查遗漏，而不是凭感觉再改一遍。

# 工序

1. 接收分析笔记的发现表（过滤出 `可修` 且携带三元组的条目）；
2. 逐条应用中文规则库（`references/rules-zh.md`，模式编号引用），英文模式不直接照搬；
3. 产出更改摘要：每处改动一行「位置 + 模式编号 + before→after」，diff 可审计；
4. 双向失败模型双检 → 五维评分 → Quick Checks。

# Quick Checks（交付前二值清单，每条唯一动作）

- [ ] 全文搜索规则库触发词表，命中数 = 0？
- [ ] 每个改动都能指回一条发现？
- [ ] 数字与专名清单与改前一致？
- [ ] 读一遍最长的那句，能一口气说完吗？
- [ ] 删掉任何一段会损失事实吗？（不会则删）

任一为否 → 定位 → 修复 → 重跑本清单。

# 不做什么

不新增观点与事实；不动源条目正文（polish 只作用于派生文本或明确授权的目标文本）；不决定输出形式（router 的事）；风格偏好不立项（没有发现条目支撑的口味修改一律拒绝）。
