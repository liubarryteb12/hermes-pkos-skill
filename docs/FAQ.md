# 常见问题（五岁小孩也能看懂）

## 基础问题

### Q: 这个项目是给谁用的？
**给有两类人：**
1. 用 AI 助手（比如 Hermes）管理知识的人——这是 AI 的"技能包"
2. 想研究"AI 如何可靠地管理数据"的开发者——这里有六个行为探针和一套防呆设计可以抄

### Q: 我需要会编程吗？
**不需要。** 装好后全部通过"说人话"驱动。你需要编程的场景只有一个：把定时维护挂到 cron/任务计划——而 README 里有现成命令可以直接抄。

### Q: 它会弄乱我的 Obsidian 库吗？
**设计上不会。** 三重保险：
1. 你的笔记永远以 Obsidian 原生格式躺着，系统只在 `_PKOS/` 文件夹里活动
2. 全库只有一个写入口（commit），其他单元只产出"候选文件"
3. AI 没有删除权限——删除必须经过 30 天缓冲区 + 人类确权

### Q: 支持中文吗？
**为中文而生。** 全文检索用中文 bigram 分词（两个字就能命中），front matter、词表、状态机全部中文友好。

## 使用问题

### Q: "整理知识库"到底会发生什么？
对 AI 说这句话会触发**消化流水线**：
```
扫描收件箱 → 每份材料判断类型 → 逐篇装配成合规条目 → 校验 → 入库
```
分批进行，每批完成会向你报进度。原件不会被删除（移到 `_processed/` 备着）。

### Q: 怎么查"我库里有没有关于 X 的东西"？
对 AI 说："查一下库里关于 X 的内容"。走 `intake.query`，从倒排索引+概念扇出图里找，输出 md + json 双格式结果。

### Q: 死链（红色 wikilink）要清理吗？
**不用急着清。** 本系统的理念：**死链是选题信号，不是垃圾**。你随手挖的坑，是未来要写的题目。只有"确认永不填的坑"才值得清——清之前系统会生成清单等你圈选。

### Q: 能同时管理多个知识库吗？
可以。每个 vault 独立初始化（`governance.bootstrap`），各自有独立的 `_PKOS/` 工作区。系统按 vault 路径隔离一切状态。

## 可靠性问题

### Q: 测试全绿就代表没问题吗？
**这套系统回答过这个问题**：曾经 4 个测试用例被标记为 known_gap（跳过），看起来全绿，实际没验证。后来全部转成真实断言（37/37, 0 skip）。
教训沉淀在探针方法论里：**自查说没问题、探针说有问题**——这个模式在六条战线上反复被验证。

### Q: AI 会不会把我的库改坏？
最坏情况的边界：
- 所有写操作有审计日志（`_PKOS/reports/commits/`）
- 状态机只进不退（回退需要 force + 检讨说明）
- 每次构建有时间戳审计文件（`.build-*.json`）
- 出问题可从 `_rollback/` 或 git 历史整体恢复

### Q: 并发安全吗？两个 AI 同时写会怎样？
安全。同一路径写入有 per-path 互斥锁（owner=pid:uuid，TTL 300s 兜底）。
抢不到锁的一方收到**明确报错**（IndexWriteError），可以重试——绝不静默写出错位数据。这是 7 条并发契约探针验证过的行为。

## 维护问题

### Q: 多久需要维护一次？
系统自带心跳（`tick.py`），每天跑一次即可：
- 收件箱堆积报警（>10 件）
- 草稿/隔离区超期清理
- 增量 lint
- `_trash` 到期提醒

可以做成 Windows 任务计划或 Hermes cron（README 有命令）。

### Q: 怎么彻底删除东西？
不能"彻底"——这是特性不是缺陷：
```
1. 移入 _trash/<今天的日期>/
2. 等 30 天（期间随时可反悔）
3. trash_gc --report 生成清单
4. 人类核对清单后给确认 token
5. trash_gc --purge --confirm-token <token> 才真删
```
junction/符号链接穿透有专门防线（reparse point 三层检查），防误删库外文件。

### Q: 我想给它加新功能怎么办？
先过**结构审计五问**（`contracts/structure-audit.md`）：
1. 和现有单元同输入同输出同时机？→ 重叠，别建
2. 是不是在抢别的单元的活？→ 职责抢占，禁止
3. 跨领域能力？→ 抽独立枢纽，别塞进现有单元
4. 政策类内容？→ 收归 contracts/ 单一真相
5. 都不是？→ 欢迎新单元，注册进 registry（schema 校验器会检查你填的元数据）

## 故障排查

| 症状 | 处置 |
|---|---|
| `upgrade_check` FAIL | 看输出里哪一项 FAIL，按提示修；通常是 registry 计数或旧路径残留 |
| `MASTER_INDEX.json 被占用` | Obsidian 开着库导致；index.py 有原子写+旁路兜底，关掉 Obsidian 重跑即可 |
| `IndexWriteError: 同路径并发写入被拒` | 另一个进程正在写同一路径，稍后重试 |
| 探针失败 | **先怀疑实现，再怀疑测试**（本项目铁律）；对照 `pkos_kb_tests/test_*_contract.py` 的注释 |
| 中文搜不到 | 确认词是 ≥2 字（bigram 分词特性）；单字用 FTS 通配 |
