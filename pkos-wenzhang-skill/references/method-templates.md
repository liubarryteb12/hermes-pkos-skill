# 六种写法的完整流程与提示词（method-templates）

> 配合 `../SKILL.md` 核心工序第 4 步使用。每种写法：适用判断 → 分步流程 → 可直接用的提示词。
> 来源：吸收 SpaceZephyr/creator-buddy gzh-longform-writer（2026-08-31），已做 PKOS 适配（素材锚点=POL-*，产物落 _Export/article/）。

## ① interview 访谈式 —— 把脑子里的东西问出来

**适用**：个人经历、复盘、年度总结、「我做了 X 之后的感受」。作者心里有货，但一写就干。

**做法**：扮演资深编辑访谈作者。**一次只问一个问题**，根据回答追问细节，问 8–10 轮，然后整理成大纲。

**关键**：追问要往**具体**走，不要往**抽象**走。

- ❌ 「你从这件事里学到了什么？」 → 得到一堆正确的废话
- ✅ 「当时具体卡在哪一步？你试了哪几种办法？哪个先成功的？」 → 得到能写进文章的细节

好的追问都指向**只有作者知道的信息**：

| 追问类型 | 例句 |
|---|---|
| 具体时刻 | 「第一次意识到不对劲是什么时候？当时在做什么？」 |
| 试错过程 | 「在成功那个办法之前，你还试过什么？为什么没成？」 |
| 具体数字 | 「大概花了多久？成本是多少？效果差多少？」 |
| 反面 | 「有没有哪次这个方法失灵了？」 |
| 对话 | 「当时对方原话是怎么说的？」 |
| 判断变化 | 「现在回头看，哪个判断是错的？」 |

**整理成稿时保留作者原话。** 用户口述里那些不通顺但生动的表达，往往比你改顺的版本更好。成稿提示词：

```
根据我们上面的对话，帮我整理成一篇公众号文章初稿：
1. 保留我的原话和表达习惯，不要改成书面语
2. 我说得不通顺但生动的地方，保留
3. 补充必要的过渡，但不要加我没说过的观点
4. 需要我补充细节的地方，用【待补：xxx】标出来
```

**PKOS 适配**：访谈轮次的问答记录落 `_PKOS/_Export/article/<route-id>-article/interview-log.md`（供溯源与 gate_1 重生成对比）。

## ② outline 大纲式 —— 把骨架撑成肉

**适用**：观点文、教程、技术解读。作者知道要说什么，缺的是展开。

**做法**：先落一份带**字数配额**的大纲，作者确认后再扩写。配额很重要——不给配额，AI 会把每部分写成一样长，导致重点被稀释。

```markdown
## 文章大纲：【标题】

主线判断（一句话）：

### 一、开头（约 200 字）
- 切入方式：【具体场景 / 一个数字 / 一个疑问】
- 要让读者立刻知道：这篇讲什么、和他什么关系

### 二、背景（约 300 字）
- 为什么是现在值得说

### 三、核心论点 1（约 600 字）
- 观点：
- 支撑案例：【具体到可验证】
- 我的判断：

### 四、核心论点 2（约 600 字）
- 观点：
- 支撑案例：
- 我的判断：

### 五、边界 / 反面（约 300 字）
- 什么情况下不成立
- 我自己踩过的坑

### 六、收束（约 300 字）
- 拉高一层的判断
- 一个明确的读者动作
```

**必须有「五」这一节。** 只讲好处不讲边界的文章，读者信任度低。

扩写提示词：

```
按这份大纲扩写成公众号文章。要求：
1. 严格按各节字数配额，不要写成每节一样长
2. 每个论点必须有具体案例，没有案例的地方标【待补案例】
3. 段落控制在手机屏 4 行以内
4. 不要用「本质上」「换句话说」「值得注意的是」
5. 不要编造数据和案例
```

## ③ continuation 续写式 —— 找出卡点再往下写

**适用**：写了一半停了（options.draft_path 必给）。

**关键动作是先诊断为什么卡住**，不要直接续：

| 症状 | 真实原因 | 解法 |
|---|---|---|
| 不知道下一段写什么 | 大纲没想清 | 退回去补大纲（转 ②） |
| 知道写什么但写不出来 | 缺具体材料 | 列缺料清单请作者补，或转 ① 访谈式挖 |
| 越写越觉得没意思 | 选题本身立不住 | 转 ⑤ 破题式换角度，别硬撑 |

第三种最常见，也最该诚实告诉作者。**硬把一个立不住的选题写完，是浪费两个人的时间。** 诊断提示词：

```
这是我写了一半的稿子，我卡住了。先不要续写。
请你先判断我卡在哪：
A. 大纲没想清楚（不知道下一段该写什么）
B. 缺具体材料（知道要写什么，但没东西可写）
C. 选题本身立不住（越写越觉得没意思）
给出判断和理由。如果是 C，直接告诉我，不要硬续。
```

## ④ material-merge 素材整合式 —— 从一堆材料里长出一条主线

**适用**：多条 POL-* / 收藏的链接、笔记、聊天记录合成一篇。

三步，一步不能省：

1. **压缩**：逐条读完，把每条压成一句话，标出核心信息。不评论，只压缩。
2. **找主线**：这些材料加在一起最能支撑哪一个判断？给 3 个候选主线，每个标出哪几条材料支撑、哪几条用不上，指出哪个候选支撑最扎实。
3. **删**：选定主线后重排材料，**明确列出要删掉的**（撑不住主线的），并确认删后主线仍成立。

> **最常见的失败是舍不得删。** 十条材料通常只有五六条真正服务于主线，剩下的塞进去文章就散。宁可少讲两个点。

## ⑤ angle 破题式 —— 同一主题，找到值得写的那个角度

**适用**：主题定了，但不知道怎么写才不撞车。

一次给 5–8 个角度，每个一句话说清 + 需要什么材料 + 谁会想看。覆盖维度：

- **反直觉**：大家都说 A，我看到的是 B
- **切身**：我拿它干了一件具体的事
- **对比**：和前身 / 竞品 / 国外同类比
- **溯源**：为什么现在才出现
- **代价**：解决了什么，又带来什么新问题
- **人群**：对某一类特定的人意味着什么
- **预测**：如果这条路走通，接下来会发生什么

挑选标准按顺序三问：

1. **只有你能写吗？** 换个作者写出来一样 → 划掉
2. **材料够吗？** 需要的案例/数据手上有吗 → 没有就换
3. **自己有判断吗？** 对角度无明确态度 → 会写成资讯，换

## ⑥ rewrite 重写式 —— 先定位病灶再动刀

**适用**：有完整成稿但不满意（options.draft_path 必给）。

**先诊断，输出病灶清单（按严重度排序，指明在第几段），再改**。常见病灶：

- **开头绕**：前三段都在铺垫 → 直接从第三段开始
- **没有我**：通篇公开信息复述 → 每个大段落至少加一句「我认为」
- **例子是编的**：「比如某公司」→ 换成具体可验证的，换不出就标【待补】
- **结论悬空**：讲一堆没落到明确判断
- **平**：每段一样长一样重要 → 砍次要，把主要的写透

**定点手术规则：只改被点名的地方，其余一个字不动；每处改动说明改了什么、为什么。**

> **「整体润色」是重写式最大的陷阱。** 它会把文章磨得更顺，同时磨掉所有个人痕迹，结果更像 AI 写的。
