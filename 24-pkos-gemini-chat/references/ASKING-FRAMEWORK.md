# Gemini 提问框架（双向角色 + 输出契约）

> v1.0 | 2026-08-29 | 来源：用户三点批评——①没声明调用方角色导致敷衍 ②没给 Gemini 定指导角色 ③缺提问方法论。
> 适用：gemini-chat / gemini-image 的 prompt 构造，以及一切「向外部 LLM 提问」的场景。

## 为什么需要框架

裸问（只丢问题）的三个失效模式：
1. **Gemini 不知道你是谁**——不知道你的技术水平、上下文、已完成的工作，只能给百科式泛答。
2. **Gemini 不知道自己该以什么身份答**——默认「友好助手」人格倾向讨好、堆砌、面面俱到但不深。
3. **没有输出契约**——不限定格式/长度/禁止项，回复就要花大篇幅寒暄和免责。

## 一、双向角色声明（每次提问必带）

```
【我是谁】<调用方角色 + 当前状态/已完成工作>
【你是谁】<要求的专家角色 + 用什么标准审视问题>
【要你做什么】<具体任务动词 + 期望产出物>
```

示例（真实场景）：
```
【我是谁】我是一个已落地的知识管理系统（PKOS v4.3）的调度 agent，
负责在 Windows 上编排 34 个能力单元，刚跑通 Gemini 网页出图链路。
【你是谁】你是资深 API 经济学与自动化架构顾问，做过大量 LLM 成本优化，
以怀疑态度审视方案（不要附和我）。
【要你做什么】评估「网页抓取通道 vs 付费 API 通道」的长期风险清单，
只列我可能没想到的失效模式，每条带检测信号。
```

## 二、输出契约（限定形状，压缩废话）

| 维度 | 指令 | 效果 |
|---|---|---|
| 结构 | 「只讲 N 点，每点 ≤2 句」 | 防面面俱到的泛答 |
| 格式 | 「直接给结论/表格/清单，不要开场白和总结」 | 砍掉寒暄与免责 |
| 深度 | 「假设我已懂基础概念，直接讲机制和坑」 | 跳过科普 |
| 证据 | 「每条判断带可观测信号/代码位置，不接受『建议关注』」 | 逼出可执行内容 |
| 禁止 | 「禁止：复述我的问题/说『这是个好问题』/给免责声明」 | 反奉承 |

## 三、反奉承尾标（默认注入，可关）

在 prompt 末尾追加：

```
回答要求：直接、可证伪、不奉承。如果你的判断与我的前提冲突，先指出冲突；
不确定就说不确定并给出验证方法，不要编。
```

为什么有用：LLM 的讨好倾向是对「隐含期待」的迎合；显式给出「允许反驳 + 要求可证伪」的许可后，反对意见出现的频率显著上升。

## 四、追问式深挖（一轮不满意时的标准动作）

1. **指出具体不满**：「第 2 点是泛泛而谈，我要的是这个模块实际会怎么挂」——不接受重新泛答。
2. **逼选择**：「A 和 B 只能选一个，说出你的判据」——二选一强制表态。
3. **换视角**：「现在你是审计这方案的对手方，列出它会死的三个原因」——角色反转挖盲区。
4. **要前兆**：「这个问题发生前 telemetry/日志里最早能看到的信号是什么」——落到可观测。

## 五、自查清单（发送前 10 秒过一遍）

- [ ] 我是谁（角色+状态）说了吗？
- [ ] 它是谁（专家身份+审视标准）定了吗？
- [ ] 产出物形状（几点/几字/什么格式）限了吗？
- [ ] 禁止项（寒暄/奉承/免责）写了吗？
- [ ] 它反驳我的空间给了吗？
- [ ] 这问题是「能回答的」还是「开放式闲聊」？（闲聊不需要本框架）

## 六、对话轮次规则（量化要求，v1.1 新增）

**任何一次「向 Gemini 提问/讨论」任务的最小轮数**——达到轮数前不得把单轮回复当作最终结论交付：

| 讨论类型 | 最低轮数 | 判定标准 | 每轮动作 |
|---|---|---|---|
| 普通对话 | **≥ 5 轮** | 简单确认、单点咨询、事实核对 | 首问 → 追问确认理解 → 要反方观点 → 逼边界条件 → 复述结论请它纠错 |
| 高强度讨论 | **≥ 20 轮** | 方案对比、架构取舍、有争议的判断 | 在 5 轮基础上：角色反转攻防（它当对手方）→ 逐条逼前兆信号 → 换视角再攻 → 要求量化判据 → 对结论做可证伪性检查 |
| 详细细致讨论 | **≥ 30 轮** | 重要设计决策、体系级评审、产出质量验收 | 在 20 轮基础上：分模块逐个深挖 → 交叉追问每条假设的来源 → 要求给出反例与失效模式穷举 → 每个结论标注置信度与验证方法 |

**执行方式**：轮数是下限不是目标——高质量收敛可以提前结束的唯一条件是「双方都没有新论点且用户已确认满意」；用户明确说「够了/就这样」可以随时提前终止。**用户有额外需求（轮数、格式、深度、方向）时，以用户要求为准，覆盖本表。**

- 追问不足轮数 = 偷懒，交付质量打折（实测：单轮回复必有泛泛而谈，深挖 3 轮后才开始出现真冲突指正）。
- 每轮追问必须携带上一轮回复的具体内容（指出哪一点不满/要它展开哪一条），禁止换话题重问。

## 七、代码化参数（gemini_chat.py 已实现）

```
--caller-role "<我是谁>"      # 拼进头部
--gemini-role "<你是谁>"      # 拼进头部
--format direct|steps|table   # 输出契约（direct=只要结论+禁止寒暄）
--raw                         # 不加任何框架，纯裸问（对比/调试用）
```

组装顺序：`【我是谁】…【你是谁】…【任务】<prompt>…<反奉承尾标>`
