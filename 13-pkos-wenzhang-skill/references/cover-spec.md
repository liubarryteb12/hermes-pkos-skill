# 公众号头图规范（cover-spec）

> 配合 `../SKILL.md` 交付环节：成稿要发公众号时，头图按本规范做。**出图通道优先免费**：默认走 `25-pkos-gemini-image`（Gemini 网页版，零成本）；仅当免费通道不可用或文字渲染不达标时才降级 `pkos.gptimage2use`（付费网关），且降级前须向用户报备（09-06 用户裁定「我的钱啊」）。机器校验走 `scripts/check_cover.py`。
> 来源：吸收 SpaceZephyr/creator-buddy space-gzh-cover 的平台事实与校验器（2026-08-31）。

## 最重要的一条：公众号封面会被裁两次

| 场景 | 显示 |
|---|---|
| 订阅号消息列表 / 文章顶部 | 完整 **2.35:1** |
| **分享到朋友圈 / 聊天** | **只抓正中央 1:1 方形**（占宽度 42.6%） |

```
|←── 左翼 28.7% ──→|←── 中央安全区 42.6% ──→|←── 右翼 28.7% ──→|
      分享时切掉          分享时唯一保得住的          分享时切掉
```

推荐画布 **1175×500**，安全区 = x 337–837 这 500px。

**实测后果**：12 字标题铺满全宽，分享出去只剩中间 6 个字，首尾各切一半，读不通。

**反直觉陷阱**：横版设计直觉是「文字左、图右」分栏——公众号封面上**任何把信息平均分到左右两侧的版式都是陷阱**，分享时两侧全切、只留中间。

## 三种安全区策略

| 策略 | 做法 | 分享效果 | 适合 |
|---|---|---|---|
| **A 全居中** | 标题全塞进安全区，≤12 字分 2 行 | 完整无损 | 靠分享传播、求稳 |
| **B 核心词居中**（默认） | 标题横铺，最关键的 4–6 字词组压正中 | 核心词完整，修饰词被切 | 大多数情况 |
| **C 图文分离** | 中央放主体图形，文字在两翼 | **分享后没有文字** | 只在文章顶部展示 |

选 B 必须**明确写出核心词组是哪几个字**，检查阶段验证在安全区内。C 要主动提醒风险再执行。

## 封面标题规则（比文章标题严）

- 总长 **6–14 个汉字，最多 2 行**（横版 3 行必挤）；封面标题 ≠ 文章标题，文章标题可以长可以带钩子，封面要短、一眼扫到
- **先圈核心词组（4–6 字）**，这部分必须在安全区
- 一行一个语义块，不在词组中间断行；中英混排保留完整英文词组；标点能省则省
- 可选短标签 ≤8 字，放胶囊里

## 出图 prompt 要点（两通道通用；文字渲染要求逐字列出，Gemini 通道注意其超长 prompt 拒答限制）

必须写明：2.35:1 横版公众号头图；需要出现的文字**逐字列出**；**哪几个字必须在中央安全区**；缩小到消息列表尺寸仍要清楚；禁止水印/账号名/无关文字/乱码中文。一次调用一张，多版分别调用并写明差异（不要只换个颜色算一版）。

## 检查（两道，都不能跳）

**第一道 机器**：`python scripts/check_cover.py cover-01.png --safe-zone --share-preview --thumbnail`
输出比例/尺寸/体积校验 + 安全区像素范围 + 三张预览图（安全区标注 / 朋友圈 1:1 实裁 / 260px 缩略）。

**第二道 肉眼**（机器查不了）：
- 主标题逐字正确？有无乱码错字？
- **打开 `-share-1x1.jpg`：核心词组还读得通吗？——读不通就是不合格，不管整图多好看**
- 打开 `-thumb.jpg`：2 秒内能读懂？
- 主标题是第一视觉？留白够？四边有安全边距？

**修正**：局部问题定向编辑（写明「仅把 X 移到中央方形区内，其余全部不变」），不整张重做。同一段文字连续两次生不对：①压短再试 → ②生成无字底图+预留标题区，文字层交给可编辑方案 → ③**绝不把有错字的图当成品交付**。
