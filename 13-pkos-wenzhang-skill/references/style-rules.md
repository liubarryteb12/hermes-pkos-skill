# 公众号文章风格规则（style-rules）

> 配合 `../SKILL.md` 核心工序第 5-6 步。人读权威版；机器可校验子集由 `scripts/article_tools.py lint` 强制执行。
> 来源：吸收 creator-buddy gzh-longform-writer / gzh-short-post 规则 + PKOS 公众号发布审核 v4 对齐项（「母题」禁词、半角标点）。

## 一、公众号五个特有约束（决定有没有人看完）

1. **开头几句要能独立成立。** 摘要不填会自动截取正文开头——第一段不能是「最近很多人在问我一个问题」这种零信息铺垫，它会原样出现在读者消息列表里。
2. **手机屏是唯一阅读场景。** 一行约 22–24 字，**单段超过 90 字（约 4 行）就该断**。桌面看着正常的段落，手机上是一堵墙。
3. **没有目录，靠小节标题导航。** 超过 2000 字必须分小节（`##`）；小节标题要扫一眼就知道这段讲什么，禁用「其一」「其二」。
4. **读者是订阅者，不是信息流路人。** 不需要开头证明你是谁，可直接进正题，可用「上一篇说到」连续性表达。
5. **结尾必须有一个明确动作。** 留言、转发、点「在看」、读上一篇、加群——**只给一个**。给三个等于没给。

## 二、三种结构骨架（一篇只用一种，混用读者失去方向感）

| 骨架 | 适合 | 形状 |
|---|---|---|
| **总分总** | 观点文、行业判断 | 亮判断 → 三根支柱 → 拉高 |
| **时间线** | 复盘、经历、产品史 | 起因 → 转折 → 结果 → 提炼 |
| **问题链** | 教程、深度解读 | 一个问题 → 答案引出下一个 → 收束 |

## 三、AI 腔黑名单（出现即改）

- 「本质上」「说白了就是」「换句话说」
- 「这意味着什么？」后面跟一句空泛概括
- 「不是 X，而是 Y」（一篇最多 1 次）
- 「值得注意的是」「综上所述」「笔者认为」「不难看出」
- 三段排比结尾（「是……，是……，更是……」）
- 每段都以「而」或「然而」开头
- 鸡汤腔：「希望对大家有帮助」「共勉」「一起加油」「愿你我都能」

**一个重要区分**：`自问自答` 本身是好节奏工具——问句独立成段，后面紧跟**具体**回答。它变成 AI 腔是因为后面跟的是抽象概括。

- ✅ 「这意味着什么？」→「以前你用 AI 写代码是 1 对 1 对话，现在它自己拆任务、自己分配、自己解决冲突。」（具体）
- ❌ 「这意味着什么？」→「这意味着 AI 正在深刻改变我们的工作方式。」（空泛，删掉不损失任何信息）

**判断标准：把问句和答句一起删，若文章没损失任何信息，就是 AI 腔，删。**

## 四、标点与格式硬规（lint 机器强制）

- 引号统一 `""`，不用「」
- 破折号 `——` 全篇 ≤2 次
- 正文全角标点（半角逗号/分号/直引号 = 发布审核 BLOCK 项）
- 不用 emoji；hashtag 仅结尾可选
- 英文产品名保持原样（Claude Code、MCP、飞书 CLI）
- 编号观点的小标题不加粗
- 「母题」一词禁入正文（文学语境豁免，对齐发布审核 v4）

## 五、成稿质检清单（输出前逐项过，附结果交付）

| 项 | 判断 | lint |
|---|---|---|
| 有没有「我」 | 至少 3 处只有作者能说的话/判断 | 人工 |
| 例子是不是真的 | 无「某公司」「某用户」式编造案例 | 机器（正则） |
| 有没有边界 | 承认什么情况下不成立 | 人工 |
| 段落长度 | 无 >90 字段落 | 机器 |
| 开头能不能独立 | 第一段抽出来单看有信息量 | 人工 |
| 结尾动作 | 只有一个且具体 | 机器（启发式） |
| 小节 | >2000 字必有 `##` | 机器 |
| AI 腔 | 黑名单词表 | 机器 |
| 字数 | long 1500–4000 / short ≤1000 | 机器 |
| 待补项 | 【待补：xxx】全部计入汇报 | 机器 |

## 六、短文规则（length_target=short，≤1000 字纯文字）

不是长文缩水版——长文靠结构取胜，短文靠**一个锐利的点 + 干净的节奏**。1000 字塞三个观点等于一个都没说清。

- **第一人称不说教**：全篇「你」≤1 次（最好 0；例外：结尾行动引导）。❌「你会发现」→ ✅「我发现」
- **敢下判断不两头讨好**：别每句「一方面……另一方面……」
- 单段超 70 字（约 3 行）就断——纯文字没配图撑场，全靠分段做呼吸
- 两种骨架二选一：**A 编号观点式**（≤4 个编号，必须有串联段——没它文章就是 list 不是 insight）/ **B 单点推进式**（拿不准选 B，1000 字讲透一个点比列四个点有记忆点）
- 编号 >4 个 → 该写长文；观点 >4 个 → 砍到 1 个或转 long
- 压缩长文为短文是**重新提炼**，不是节选
- 平台事实：图文消息正文无上限（1000 字是编辑目标）；纯文字群发 ≤300 字且去标题；自动回复 ≤600 字

## 七、红线（与 SKILL.md 一致，此处为执行细则）

- 不编造案例、数据、引用、人名；没素材就标【待补】
- 不替作者表达他没表达过的立场
- 不把推测写成事实、相关写成因果
- 保持作者立场和锋芒，**不中和掉原文的判断**
