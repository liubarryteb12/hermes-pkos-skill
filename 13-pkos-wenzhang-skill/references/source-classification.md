# 素材来源分类与创作规范（source-classification）

> 配合 `../SKILL.md` 核心工序第 2-3 步使用。
> 解决的问题：不同来源的素材需要完全不同的写作口吻和结构。混淆来源类型 = 以"我"为主体声称他人原创内容 + 未标注出处 + 纯搬运无独立价值。

---

## 一、分类框架

| 类型 | 定义 | 写作模式 | 核心口吻 |
|---|---|---|---|
| **用户原创** | 用户自己经历、自己做的 | ①②③④⑤⑥（按需选） | "我做了/我用/我发现"（第一人称经历） |
| **转载** | 他人原创，用户剪藏/收藏 | ⑦ resource-curate（强制） | "我发现/我挖掘到了/我整理了"（策展者视角） |
| **数据挖掘** | 公开数据，用户整理分析 | ② outline 或 ④ material-merge | "我分析了/我整理了"（分析者视角） |
| **官方整理** | 官方公告/文档，用户解读 | ② outline 或 ⑤ angle | "官方发布/我梳理了"（信息整理者视角） |

---

## 二、检测方法

检查源文件 front matter：

| 字段 | 判定规则 |
|---|---|
| `type: tool` | 大概率用户原创（需检查 author） |
| `type: clipping` + 有 author | 转载 |
| 有 source（非自有域名）+ 有 author | 转载 |
| 有 source（官方域名）无 author | 官方整理 |
| 有 source（API/数据集）无 author | 数据挖掘 |
| 无 source、无 author、无 published | 用户原创 |

**快速流程**：`type=clipping` → 转载 → ⑦；`type=tool` 且无外部 author → 用户原创 → 按需选模式；其他情况按 source 域名判断。

---

## 三、resource-curate 资源策展式

**适用**：素材为他人原创内容（`type=clipping`），用户剪藏了别人的教程/文章/帖子。

**核心原则**：策展人不是原作者。价值在于"发现"和"筛选"，不是"创作"。

### 结构骨架

```
# 标题（资源发现型）

> 素材来源：@作者 发布于 X/博客/视频
> 原文：https://...
> 发布日期：YYYY-MM-DD

## 01 我为什么注意到它
- 我遇到的场景/痛点
- 怎么发现的
- 为什么值得分享

## 02 它是什么
- 一句话介绍
- 核心亮点（提炼原文，≤3个）

## 03 我的判断
- 适用场景：谁适合用？
- 价值判断：值不值得投入时间？
- 局限与风险

## 04 延伸入口
- 想深入了解去哪看
- 相关资源

## 写在最后
- 一句话总结
- 引导行动（阅读原文/试用/收藏）
```

### 口吻转换表

| 错误 | 正确 |
|---|---|
| "我搭建了X" | "我发现了一套X的教程" |
| "我花了Y元买Z" | "我发现了一篇关于Z的拆解" |
| "我做了个工具" | "我发现了一个开源工具" |
| "我的经验是" | "他的核心观点是" |
| "我踩过的坑" | "他提到的一个坑是" |

**关键**："我做了X" = 你是X的创造者（仅原创）；"我发现X" = 你是X的发现者（转载必用）

### 出处标注（必须）

格式：
```
> 素材来源：@作者 发布于 平台
> 原文：URL
> 发布日期：YYYY-MM-DD
```

位置：标题下方，正文第一段之前。

### 独立价值（必须增补至少2项）

| 类型 | 示例 |
|---|---|
| 适用场景 | "适合有编码基础的用户，纯小白可能卡在第3步" |
| 价值判断 | "和tokentab比多了图表，但少了Codex支持" |
| 延伸入口 | "想深入：GitHub有完整文档" |
| 读者视角 | "第5步我试了三次才跑通" |
| 时效提醒 | "数据是8月的，可能已有变化" |

### 二创说明

"二创"不是"洗稿"。区别：

| 维度 | 洗稿 | 二创 |
|---|---|---|
| 原创占比 | <30% | >50% |
| 视角 | 转述他人 | 自己的解读/延伸 |
| 结构 | 沿用原文 | 重新组织 |
| 出处 | 不标注 | 标注 |

二创的判定：删掉你的部分后，剩下的是独立素材而非原文翻译 = 合格。

### 禁用模式

| 禁用 | 原因 |
|---|---|
| "我做了/我有/我买了X" | 暗示原创，实际是转载 |
| "我的经验/我的方法" | 暗示亲测，实际是转述 |
| 不标注出处 | 知识产权风险 |
| 大段引用 >200字 | 洗稿嫌疑 |
| 无独立价值增补 | 纯搬运 |

---

## 四、数据挖掘与官方整理规则

### 数据挖掘
- 口吻："我分析了/我整理了"
- 出处：标注数据来源（API名+日期）
- 必须有分析视角，不只是数据罗列

### 官方整理
- 口吻："官方发布了/我梳理了"
- 出处：标注官方原文链接
- 区分"官方说的"和"我的判断"
- 标注"未证实"内容

---

## 五、写作方案映射

| 素材类型 | 推荐写法 | 标题风格 | 结构 |
|---|---|---|---|
| 用户原创 | interview/outline/continuation | "我做了X/我的X" | 按选题需要选 |
| 转载 | resource-curate | "我发现X/我挖掘到X" | 总分总（发现→介绍→判断） |
| 数据挖掘 | outline/material-merge | "我分析了X/数据告诉你" | 问题链/时间线 |
| 官方整理 | outline/angle | "官方发布X/我梳理了X" | 总分总 |

---

## 六、质检清单（转载内容专用）

| 项 | 判断 |
|---|---|
| 出处标注 | 有作者+平台+链接+日期 |
| 口吻正确 | 无"我做了/我有/我买了"等原创暗示 |
| 独立价值 | 至少增补2项 |
| 非纯翻译 | 删掉增补部分后不是原文翻译 |
| 大段引用 | 无>200字直接引用 |
| 判断归属 | 区分"原文观点"和"我的判断" |
