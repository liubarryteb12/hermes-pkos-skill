# 三层架构（v2.0 用户裁定，职责单一）

```
29-pkos-trend（热点信号采集，外置单元）
  → 产出 trend-digest 情报单（只有信号与热度证据，不做决策）
28-pkos-topic（选题决策 = 本单元）
  → 母题/栏目规划 + 选题池评分 + 标题生成
08-pkos-router → 13-pkos-wenzhang-skill（统一文案出口，唯一）
  → 文案风格模板注册库在其 references/voice-styles.md，选题单以 style_hint 字段传递建议
```

追热点是信号采集（29 的事），不是选题决策（本单元的事）；本单元需要热点输入时**消费 29 的情报单**，不自己临时搜（兜底除外，见 Procedure）。

# 职责一：母题/栏目运营（产品经理视角）

- **母题提案**：新母题 = 定位一句话 + 受众画像 + 更新节奏 + 差异化理由 + 3 条代表选题。提案落 `_PKOS/INBOX/`（type=method, status=raw）走 intake 链，本单元不直接写 vault（D-6）。
- **栏目矩阵**：既有母题 × 新提案放同一张表里看：各母题的受众重叠度、更新间隔、近 4 期数据表现，避免栏目同质化。
- **排期建议**：按时效性分池——时效池（周级，热点相关）+ 常青池（月级，教程/复盘）+ 情绪池（机动），给出「本周写哪个」的排序建议。

# 职责二：选题池与评分（产品运营视角）

选题池每条打五维分（各 1-5，总分 25，≥18 进本周排期）：

| 维度 | 判据 |
|---|---|
| 时效 | 热点窗口内 5，常青题材 2-3 |
| 受众宽度 | 覆盖公众号主力读者画像 5，窄垂类 2 |
| 兑现成本 | 素材在手可完全兑现 5（**低成本低分**：兑现要编造/缺数据 1） |
| 差异化 | 与既有文章/母题不重叠 5，同题已写 1 |
| 系列潜力 | 能撑起 ≥3 篇连续内容 5，一次性题材 1 |

硬红线（继承 PKOS 不编造事实公理）：兑现成本维度不给「编数据也能写」的选题高分；社会证明类标题没有公开数据不启用。

# 职责三：标题生成（v1 资产，保留）

方法论资产（references/，吸收自上游 MIT 仓库，保留原始出处）：

- `references/topic-templates.md` — 8 个选题模板（必装清单/亲测复盘/从0到1教程/热点产品落地/对比抉择/开源神器安利/身份场景化/反常识情绪钩）。**路径 B 必读。**
- `references/title-formulas.md` — 7 型标题公式（数字清单/我+代价+收获/反转结论/速成教程/社会证明/对比站队/情绪短句）。**A/B 都读。**
- `references/title-corpus.md` — 真实爆款标题语料，只校准句式，不复述成新标题。
- `references/qa-checklist.md` — 发出前 QA 清单（确定性子集 = scripts/qa_check.py）。

## 路由

| 用户给了什么 | 路径 |
|---|---|
| 文章描述、草稿、草稿标题、明确主题句，或说「帮我起标题」 | **A** 只出标题 |
| 关键词、想法、「最近写点什么」、空输入、或说「做选题规划/栏目怎么排」 | **B** 内容运营选题方案 |

## 路径 A（有选题 → 候选标题，同 v1）

1. 读 `references/title-formulas.md`（需要校准句式读 `title-corpus.md`）。
2. 抽可钩元素：对象工具、身份、数字、结果、冲突、代价、附赠物。缺数字/身份按公式文档合理补全**并标注需兑现**；不编造 Star、下载量、实验样本量。
3. 覆盖 6 个不同公式，默认 6 条；情绪短句最多 1 条；禁止同义改写。
4. 机器自检：`python scripts/qa_check.py <产出md> --path A`，exit 0 才交付。
5. 输出：`## 选题理解` → `## 候选标题`（6 条：标题/公式/字数/为何可能点/兑现）→ `## 首选`。

## 路径 B（无选题/要规划 → 内容运营选题方案，v2.0 重写）

1. 读 `references/topic-templates.md` + `references/title-formulas.md`。
2. **取热点输入**：优先读 `_PKOS/analysis/trend-digest-latest.md`（29-pkos-trend 产物）；没有才 WebSearch 兜底并注明。不从语料抄过时产品名。
3. 出 **4 个母题级方向**，每个方向必须含：母题名（建议编号延续既有系列）、模板、定位一句话、受众、更新节奏、差异化理由、**3 条代表选题**（标题+公式+字数+兑现）。
4. 附**选题池评分表**（五维打分 + 总分排序）。
5. 机器自检：`python scripts/qa_check.py <产出md> --path B`，exit 0 才交付。
6. 收口 `## 最值得先写`：一个母题 + 首篇标题（时效 × 受众 × 可执行，一句）。

# 边界声明

- **与 29-pkos-trend**：trend 只采集不决策（不做选题、不写标题）；本单元只决策不采集（热点一律消费 trend-digest，兜底搜索须注明）。
- **与 13-pkos-wenzhang**：本单元=成稿前（想法→选题→标题→排期）；wenzhang=成稿后出口（article.md + titles.md 收口）。文案风格模板注册库在 wenzhang `references/voice-styles.md`；选题单可带 `style_hint` 建议字段（如 style: 保姆级教程），由 wenzhang 消费，本单元不定义风格。

# 硬规则

- 只做选题、规划、标题。不写正文/大纲/配图；用户说「按这个写」→ 交 `08-pkos-router`（exit=article）→ `13-pkos-wenzhang-skill`。
- 标题写了附教程/提示词/开源仓库，兑现点必须写明对应物从哪来。
- 禁：震惊/重磅/炸裂/通稿体/空数字（「多个」「一系列」）。
- 换赛道只搬公式槽位，不搬语料产品名（Codex/WorkBuddy/Skill 等）。
- 主标题 18–32 字，工具名尽量进前 16 字。

## 承接关系契约（09-06 用户裁定，排期与成稿共同遵守）

- 连续性**只存在于母题内部纵向**：同母题子题之间可以有上下文承接（上一篇/下一篇钩子、系列递进 07-01-01 → 07-01-02 → 07-02-01）。
- **禁止跨母题承接**：任何文章不得在正文引用、预告、回顾其它母题/合集的内容（如 09-AI办公室 的文章不得提 08-AI热榜观察 的选题）。各母题是独立连载线。
- 母题 EP01（该线首篇）不得虚构「上一篇」；收尾不硬造连载感。
- 排期时：某母题线内的下一篇选题，必须与本篇构成子题递进，不从别的母题借上下文。
- article 出口 lint 的 C1/C3 规则在本契约下执行机器兜底（见 13-pkos-wenzhang-skill/scripts/article_tools.py）。
